# 최신 화면 매핑

기준 Figma는 `예소_팀 이삼사`, 노드 `2570:11890`입니다. 다이어리와 캘린더는 최신
완성 화면을 우선하고, 센서 기능은 담당자가 제공할 별도 계약과 연결합니다.

## 1. 인증

| 화면 | 기능 | 서버·외부 계약 |
|---|---|---|
| 로그인 | 이메일·비밀번호, Naver·Kakao·Apple | Supabase Auth |
| 회원가입 | 필수 약관, 이메일 인증, 비밀번호·확인, 닉네임 | Supabase Auth metadata |
| OAuth 추가 정보 | 최초 로그인 닉네임 | `PATCH /users/me` |
| 비밀번호 찾기 | 이메일로 재설정 링크 발송 | Supabase Auth |
| 비밀번호 변경 | 딥링크 복귀 후 앱에서 새 비밀번호 | Supabase Auth |

## 2. 식물 등록

1. 애칭을 입력합니다.
2. 정확한 지원 23종을 검색하거나 카메라·갤러리 사진으로 인식합니다.
3. 인식 결과에서 식물명, 식물과, 개화기 등을 확인합니다.
4. `아니에요`는 다음 후보를 표시하고 후보가 없으면 검색 화면으로 이동합니다.
5. 인식 사진은 식물 대표 사진으로 사용합니다.
6. 장소 별명, 식물 시작일, 마지막 물 준 날과 선택적 분갈이 날짜를 입력합니다.
7. 여섯 성격 중 하나를 고릅니다.
8. 컬러와 헤어를 고르고 완성 화면에서 등록합니다.

등록 초안은 앱 종료에도 복원하도록 Flutter 로컬 저장소에 둡니다. 대분류, 화분 재질,
위치 분류, 장식과 컨디션은 입력하지 않습니다.

## 3. 홈과 식물 관리

| 영역 | 기능 |
|---|---|
| 식물 방 | 선택 식물을 표시하고 좌우 스와이프로 전환 |
| 상단 | 식물 시작일 기반 `D+`, 알림, 우편함 진입 |
| 배경 | 사용자 시간에 따라 낮·밤 등으로 변경 |
| 해 아이콘 | 교감 애니메이션만 실행 |
| 캐릭터 | 성격별 고정 대사, 센서 담당 결과에 따른 표정 표시 |
| 전체 보기 | 모든 식물, 추가, 수정 모드의 삭제 |
| 삭제 | 확인 팝업 후 식물 삭제 |
| 정보 수정 | 애칭과 장소 별명 변경; 종·시작일·성격·관리 이력 변경은 제외 |
| 꾸미기 | 컬러와 헤어 변경 |
| 진단 | 독립 진단 촬영 화면으로 이동 |

홈에는 AI 채팅, 오늘 메모, 자유 할 일과 수동 컨디션이 없습니다. Figma에 식물 시작일
입력칸이 명시적으로 보이지 않더라도 `D+`와 식물 생년월일의 기준이므로 등록값으로
유지해야 합니다.

## 4. 캘린더

- 월별·주별 전환을 지원합니다.
- 물주기, 분갈이, 비료 일정만 표시합니다.
- 선택 날짜 또는 주의 일정 목록과 완료 상태를 표시합니다.
- 과거에 수행했지만 체크하지 못한 일정은 해당 날짜에서 완료 처리할 수 있습니다.
- 비료 일정은 추가 버튼과 날짜 선택 화면에서 만듭니다.
- 가지치기, 컨디션과 자유 할 일은 표시하지 않습니다.

## 5. 다이어리

- 월 달력에서 기록이 있는 날짜를 구분합니다.
- 식물별·날짜별 다이어리는 한 건입니다.
- 작성·상세 화면은 날짜, 날씨, 제목, 본문과 선택 사진 한 장을 사용합니다.
- 카메라와 갤러리를 모두 허용합니다.
- 기존 기록은 수정할 수 있습니다.
- 컨디션 점수, 월별 컨디션 그래프와 통계는 제거합니다.
- 첫 생성 시 5~15분 뒤 도착할 편지 한 통을 예약합니다.

## 6. 우편함과 편지

- 우편함 목록은 사용자의 모든 식물이 보낸 편지를 최신순으로 표시하고 읽지 않은 편지를
  구분합니다.
- 편지를 누르면 식물이 보낸 본문을 표시하고 읽음 처리합니다.
- 목록 스와이프로 삭제하며 확인 팝업을 표시합니다.
- 편지 삭제는 다이어리를 삭제하지 않습니다.
- 다이어리 수정은 이미 완성된 편지를 변경하거나 추가 생성하지 않습니다.
- 편지 도착 시 알림함에 항목을 추가합니다.

## 7. 진단

1. 카메라 또는 갤러리에서 진단 사진 한 장을 선택합니다.
2. 분석 중 화면을 표시합니다.
3. 결과는 사진, 요약, 관찰 증상, 원인 확률과 추천 관리를 보여줍니다.
4. 진단표에서 오늘 진단과 과거 이력을 확인하고 상세로 이동합니다.
5. 재촬영이 필요하거나 실패한 경우 재시도할 수 있습니다.

진단은 채팅과 연결하지 않으며 별도의 대화 UI가 없습니다.

## 8. 알림

- 오늘과 이전 알림으로 구분합니다.
- 읽지 않은 항목은 빨간 표시, 읽은 항목은 비활성 표시를 사용합니다.
- 편지 도착과 관리 일정 알림은 대상 화면으로 이동합니다.
- 센서 알림의 발생 조건은 센서 담당 영역이지만 동일한 알림 목록과 읽음 처리를 사용합니다.

## 9. 마이페이지

- 닉네임, 이메일과 식물을 키운 기간을 표시합니다.
- 닉네임 변경, 비밀번호 변경, 앱 알림 ON/OFF, 로그아웃과 회원 탈퇴를 제공합니다.
- 프로필 사진과 한 줄 소개는 제공하지 않습니다.

## 10. 공통 상태 화면

- 식물 없음과 첫 식물 등록 유도
- 등록 초안 복원 또는 폐기
- 사진 권한 거부와 업로드 실패
- 인식 후보 없음과 직접 검색 이동
- 장치 연결 필요 상태
- 편지 생성 대기·실패
- 진단 처리 중·재촬영 필요·실패
- 우편함·알림·다이어리·캘린더 빈 상태
- 네트워크 단절과 재시도

## 11. 센서 담당 경계

화면에는 장치 연결, 습도·조도 기반 표정과 센서 알림이 존재합니다. 그러나 장치 탐색,
Wi-Fi 등록, 원시 측정값, 일별 조도 누적, 물 요구·급수 완료 판정과 상태 산출 방식은 이
문서에서 정의하지 않습니다. 앱과 백엔드는 센서 담당자가 확정한 결과 계약을 소비합니다.
