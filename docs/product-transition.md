# 편지 기반 개편: 확정 사항과 구현 경계

## 문서와 코드의 상태

이 문서는 제품 목표이며 현재 배포 완료를 의미하지 않습니다. API 주소의 `/api/v1`은
유지하되 기존 계약을 바꾸는 기능별 PR에서 OpenAPI, migration과 앱 적용 순서를 함께
검토합니다. 기존 인증·푸시·사진 인식·진단 코드를 재사용합니다.

## 확정된 변경

- AI 채팅을 제거하고 다이어리에 대응하는 LLM 편지를 제공합니다.
- 다이어리 한 건당 편지는 한 통이며 5~15분 랜덤 도착을 목표로 합니다.
- 다이어리를 수정해도 생성된 편지는 유지합니다.
- 식물 시작일은 생년월일과 D+의 기준입니다. 분갈이 날짜는 선택 입력입니다.
- 인식에서 아니에요를 누르면 다음 후보, 후보가 없으면 검색으로 이동합니다.
- 수동 컨디션 필드와 가지치기 일정을 제거합니다.
- 홈 해 아이콘은 교감 애니메이션, 배경은 시간대별 표시입니다.
- 센서 데이터·장치 연결·집계·판정은 다른 담당자의 문서와 구현 범위입니다.

## 구현 전에 확정할 세부 계약

다음은 문서 초안의 제안값입니다. 이슈에서 결론을 기록한 후 API와 migration에 반영합니다.

| 항목 | 현재 초안 / 확인할 내용 |
|---|---|
| 다이어리 | 날씨 코드 목록, 제목 길이, 기존 데이터의 제목·날씨 채움 정책 |
| 우편함 | 전체 식물 통합 목록과 식물 필터, 삭제·읽음 동작의 최종 화면 확인 |
| 정보 수정 | 애칭·장소만 허용하는 이전 합의와 최신 화면의 관리 날짜 입력 차이 확인 |
| 분갈이 | 선택 날짜 미입력 시 최초 일정 생략, 이미 예정된 분갈이에 대한 추가 동작 |
| 급수 | 기존 반복 일정과 센서 기반 물 요구가 함께 있을 때 중복 일정·알림의 책임 |
| 홈 | 낮·밤 등 시간 구간 경계와 대사 선택 규칙; 센서 상태 코드는 담당자 결정 |
| 프로필 | 집사 기간 계산 기준은 기존 구현과 앱 계약을 유지하고 임의 변경하지 않음 |

종 선택은 7개 대분류가 아닌 기존 23개 카탈로그 항목입니다. 모든 항목이 생물학적
단일 종인 것은 아니며 선인장은 `Cactaceae` 과 수준인 기존 예외를 유지합니다.

## 편지 처리 원칙

- DB에 저장할 예약 시각과 실제 도착 시각을 구분합니다. 생성 시작을 15분 뒤로 잡으면
  외부 API 처리 시간 때문에 도착이 15분을 넘을 수 있습니다.
- 정상 동작 시 5~15분 도착을 맞추려면 생성과 공개를 분리하거나 예약 전 생성을
  완료해야 합니다. 구현 이슈에서 한 가지 방식을 선택하고 문서를 동기화합니다.
- 외부 API 장애에 따른 지연은 별도 실패·재시도 상태로 다룹니다.
- 생성 입력은 Worker가 선점하여 읽은 시점의 스냅샷입니다. 그 이후 수정은 진행 중인
  외부 요청을 재시작하지 않으며 완성된 편지는 불변입니다.
- 다이어리의 사용자가 쓴 내용은 모델 명령이 아닌 자료로 취급합니다. 편지 생성에는
  업무 변경 Tool Calling이 필요하지 않습니다.
- 편지 unique는 soft delete 후에도 유지하여 삭제 후 재생성을 막습니다.
- 편지 완료 저장, 도착 알림 생성과 Queue 등록은 원자적으로 처리합니다. Worker 재전달이
  중복 편지·중복 알림을 만들지 않아야 합니다.
- 장기 PROCESSING 복구, 재시도 한도와 삭제된 식물의 작업 취소를 구현합니다.
- 센서 요약의 실제 필드명은 확정하지 않습니다. 연동 전 테스트에서는 fixture를 사용하고
  운영 센서 값을 임의로 생성하지 않습니다.

## DB 전환 원칙

### 진단 분리 migration (#43)

`a7d921e4b603`은 `diagnoses.related_conversation_id`의 FK와 컬럼만 제거합니다.
진단 결과, 사진, 기존 채팅 메시지와 진단 완료 알림은 보존합니다. 역방향의 기존
`ai_messages.related_diagnosis_id`는 채팅 폐기 #49에서 정리합니다.

기존 API·Worker는 제거할 컬럼을 참조하므로 배포 시 구버전 프로세스를 중지하고 진행
작업을 마친 뒤 migration을 적용하고 새 API·Worker를 시작합니다. 앱 요청에서도
`conversation_id`를 제거해야 합니다. 이번 PR은 공유 DB에 migration을 자동 적용하지 않습니다.

downgrade는 nullable 컬럼과 FK만 복구하며 이전 연결값을 복원하지 못합니다. 연결값 복구가
필요하면 적용 전 백업이 필요합니다.

### 공통 원칙

- 기존 migration을 지우지 않고 새 revision으로 변경합니다.
- ERD의 표는 변경 대상 중심의 개념 요약입니다. 생략된 기존 보안·감사·멱등성 필드를
  삭제 대상으로 해석하지 않습니다. 기존 필드명은 기능상 필요한 경우에만 변경합니다.
- 채팅 관련 FK와 미디어 참조를 제거하기 전에 호출 경로와 삭제 작업을 먼저 정리합니다.
- 기존 다이어리에 편지를 소급 생성할지는 명시적 정책 없이는 실행하지 않습니다.
- 운영 데이터 삭제가 필요한 migration은 대상 행 수·백업·복구 한계를 PR에 기록하고
  실제 DB 적용 단계에서 확인합니다. 이번 문서 PR은 DB를 변경하지 않습니다.
