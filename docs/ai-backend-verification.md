## 실제 Provider 호출

사용자가 이 검증을 위해 제공한 바질 사진으로 각각 한 번만 호출했습니다.
API 키, 원본 사진, 공급자 응답 식별자는 저장소에 기록하지 않습니다.

| 경로 | 결과 | 범위 |
|---|---|---|
| 로컬 사진 품질 검사 | 통과 | 선명도·밝기 검사; 로컬 검사만으로 식물 여부를 확정하지 않음 |
| Pl@ntNet | 1순위 `Ocimum basilicum`, 확률 `0.87121` | 실제 API 키·이미지 전송·응답 정규화 성공 |
| Kindwise | `HEALTHY`, `건강해 보여요`, 원인 후보 없음 | 실제 API 키·이미지 전송·응답 정규화 성공 |
| 추천 관리 | 현재 관리 유지 및 정기적인 상태 확인 | 기존 건강 판정용 관리 문구; 점수·ml 물양을 만들지 않음 |

이는 사진 한 장의 공급자 응답 확인이지 진단 정확도 평가가 아닙니다. OpenAI는 이번에
추가 호출하지 않았습니다. 기존 단독 호출 기록과 미연결 부분은 [편지 가이드](letter-integration.md)를
따릅니다. 실제 센서 값이 포함된 편지의 end-to-end 검증을 통과했다는 의미가 아닙니다.

## 수정 및 회귀 검증

- 삭제된 식물·삭제 중/실패한 계정·삭제된 미디어의 진단/종인식 작업 시작을 차단합니다.
- 외부 응답이 도착한 뒤에도 활성 계정·식물·미디어를 다시 확인합니다. 삭제 이후 결과와
  진단 완료 알림을 새로 저장하지 않습니다.
- 진단은 기존 편지·삭제와 같은 계정 → 식물 → 하위 데이터 잠금 순서를 사용합니다.
  진단 재시도·취소의 조회 잠금도 이 순서에 맞춰 역순 잠금을 피합니다.
- 종인식 완료·실패는 행 잠금 아래 상태를 확인하여 완료 결과를 실패로 덮어쓰지 않습니다.
- `test_ai_workflow_postgres.py`는 실제 PostgreSQL에서 삭제·늦은 응답·동시 삭제·중복 완료와
  진단 결과/알림 트랜잭션 rollback을 확인합니다.
- 같은 파일의 HTTP 흐름 테스트는 presign → 업로드 완료 → 진단/종인식 생성 → Worker →
  상세 조회, 요청 재전송·타인 접근 거절을 검증합니다. 이 테스트의 Storage·Queue·Provider는
  테스트 대역이며 실제 Supabase Storage/pgmq까지 연결한 검증과 구분합니다.
- CI에서 AI·편지·관리 일정·센서 테스트 전용 DB를 모두 준비합니다. 기존 센서 DB 테스트가
  환경변수 누락으로 skip되지 않게 합니다. 테스트는 localhost의 지정된 전용 DB만 허용합니다.
- 새 migration은 없습니다. 단일 Alembic head는 `b7e3a91d6f20`입니다.
- 로컬 PostgreSQL 17의 AI·편지·관리 일정·센서 전용 DB를 사용한 전체 테스트:
  **472 passed, 0 skipped**. Starlette 테스트 클라이언트 의존성 deprecation 경고 1건.
  Ruff, `pip check`, `git diff --check` 통과.

## 센서 계약: 있음과 미정의 구분

| 항목 | 문서상 상태 | 이번 처리 |
|---|---|---|
| 기기 등록·claim | [API 명세 14절](api-spec.md)의 경로·JWT·TTL·오류·토큰 규칙 있음 | 센서 담당 #96/#97 범위. 대신 구현하지 않음 |
| 원시 측정값 수신/저장 | [telemetry 문서](sensor-telemetry.md)의 `created_at`·`lux`·`soilRaw`, DB·SQS 규칙 있음 | 기존 DB 회귀 테스트 실행, 수집 규칙 변경 없음 |
| 편지 소비 인터페이스 | `LetterSensorSummary.read(plant_id, diary_date) -> str`, 최대 4000자·오류 처리 있음 | 기존 Worker/Provider 테스트 유지 |
| 누적 조도·급수 판정 | 측정값에서 해당 날짜 결과를 산출하는 방식·임계값·확정 결과 조회 계약 없음 | 계산을 임의 구현하지 않음 |
| 홈 상태·센서 알림 | 책임 경계는 있지만 구체 상태 산출·이벤트 중복/복구 규칙 없음 | 임의 상태·알림을 만들지 않음 |

인터페이스가 있다는 것과 실제 요약 조회 구현이 준비됐다는 것은 다릅니다.
`UnconfiguredLetterSensorSummary`는 유지하며 `LETTER_GENERATION_ENABLED`를 켜지 않습니다.
센서 요약이 준비되면 기존 어댑터 자리에 연결하면 됩니다.

## 아직 완료로 표시하지 않는 검증

- 실제 Supabase JWT·Storage·pgmq와 실행 중인 API/Worker를 함께 사용한 배포 환경 검증.
- 센서 기기 등록/claim/식물 연결 이후 날짜별 요약 → 편지 생성/공개 → 인앱 알림 전체 흐름.
- 실제 iPhone 촬영·권한·앨범·화면 렌더링: 프론트와 공동 검증 영역.
- 외부 푸시 수신: 대회 범위에서 제외. 인앱 알림 기능은 유지합니다.
