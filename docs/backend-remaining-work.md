## 공유 개발 DB 적용 기록

사용자 승인으로 2026-09-28에 로컬 설정이 가리키는 공유 Supabase PostgreSQL에 적용했습니다.

```text
a9d4e7f2c610
  -> cd31c92afd23  센서 테이블 4개와 sensor_ingest 역할
  -> b7e3a91d6f20  care_events.previous_request_hashes
```

- 최종 `alembic current`: `b7e3a91d6f20 (head)`.
- `sensor_devices`, `sensor_device_claims`, `plant_sensor_devices`, `sensor_readings` 존재 확인.
- 네 테이블 RLS 활성, `anon`/`authenticated` SELECT 권한 없음 확인.
- `sensor_ingest`는 네 테이블 중 `sensor_readings`에만 INSERT 가능하며 SELECT 불가 확인.
- `previous_request_hashes`: JSONB, NOT NULL, 기본값 `{}` 확인.
- 기존 행 삭제, DB downgrade, 센서 비밀번호 설정, AWS 자원 생성/배포는 하지 않았습니다.

공유 DB에 먼저 적용했던 분갈이 revision은 #110을 통해 main에도 병합되었습니다.
팀원은 최신 main의 revision 파일을 가져온 뒤 migration 상태를 확인합니다.
오래된 main에서 알 수 없는 revision 오류가 나더라도 `stamp`나 downgrade로 숨기지 않습니다.
스키마 적용만으로 이미 실행 중인 API/Worker 코드가 갱신되지는 않으므로 새 코드 배포/재시작도
필요합니다. 기존 코드에서 이미 덮어써 유실된 요청 ID는 이번 변경으로 복구되지 않습니다.
