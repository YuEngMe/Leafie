# 출시 점검표

## 자동 검증

```bash
cd backend
pip check
test "$(alembic heads | wc -l | tr -d ' ')" = "1"
ruff check .
pytest
```

## 계약과 데이터

- Alembic migration이 단일 head이고 공유 DB가 최신 head입니다.
- `public`의 사용자 데이터 테이블에 RLS가 활성화되어 있습니다.
- 채팅, Tool Calling, 컨디션, 가지치기와 자유 할 일 계약이 API와 문서에 남아 있지 않습니다.
- 식물 등록의 마지막 물 준 날과 분갈이 날짜가 nullable이고 다이어리에 날씨와 제목이 있습니다.
- `letters(diary_id)` unique와 완료 편지 불변 규칙이 DB·서비스에서 모두 보장됩니다.
- 센서 소유 테이블과 판정 로직은 센서 담당 migration과 충돌하지 않습니다.

## 백엔드와 Worker

- Pl@ntNet 식물 인식, Kindwise 진단, OpenAI 편지 생성 실제 요청이 성공합니다.
- 다이어리 생성과 5~15분 편지 예약이 한 트랜잭션입니다.
- 스냅샷 조회 전 수정은 최신 내용, 이후 수정은 요청 재시작 없이 기존 편지 유지로 동작합니다.
- 생성은 커밋 직후 시작하고 공개 전 본문·미확인 개수·알림은 노출되지 않습니다.
- 지연 완료 시 공개 및 실제 공개 시각 기록, 전환 이전 다이어리 소급 생성 금지를 검증합니다.
- Queue 재전달, 동시 선점, 인증 실패, timeout·429·5xx, 재시도 소진을 테스트합니다.
- 편지 공개 시 알림은 한 번만 생성되고 푸시 사용자 설정을 존중합니다.
- 빈 인식 후보는 최종 실패 처리되며 재시도 상태로 덮이지 않습니다.
- FCM Worker는 활성 FID 재확인, 무효 FID 폐기와 일시 오류 재시도를 처리합니다.

## 앱 흐름

- 이메일 인증, 비밀번호 재설정과 Naver·Kakao·Apple OAuth 딥링크를 확인합니다.
- 식물 등록 초안 복원, 23종 검색, 인식 후보 순회와 대표 사진 재사용을 확인합니다.
- 홈의 D+, 시간대 배경, 성격 대사, 우편·알림 개수와 식물 전환을 확인합니다.
- 월·주 캘린더에 물주기·분갈이·비료만 표시되고 과거 완료가 가능합니다.
- 다이어리 작성, 편지 도착, 우편함 읽음·삭제와 알림 이동을 한 흐름으로 확인합니다.
- 진단 촬영, 처리 중, 결과, 이력, 재촬영과 실패 상태를 확인합니다.
- 식물 삭제와 회원 탈퇴 후 관련 데이터와 미디어가 노출되지 않습니다.
